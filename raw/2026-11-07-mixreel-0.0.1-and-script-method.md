# 写脚本方法的改动（MixReel-team#17，11-07 合并）

1. 先写主旨再写镜头。主旨交代她想要的感情类型、片子形式和她一步步得到这份感受的经过，产品只是手段。王博的格式是「这是一个【感情类型】的【现实-游戏 / 游戏内】情景剧」加经过。有现实场景时，现实那场戏要给出一个缺口或对比让游戏回应；本身就很 drama 的现实场景（比如前任婚礼）接不上。
2. 经过从已经被大量观众买过账的高潮里借机制，不借剧情和人名，按这部作品人物自己的性格来演。爽点要在同一场连续的戏里落地；之前的事隔多久都行，一句台词、一行字幕或一个镜头能交代就行；靠观众感到时间流逝的原型（隔天打脸、练了几周）不适合短片。产品本身跨时间起作用（故事结束后来的消息）不受限。
3. 按拍写镜头。一个人连贯的动作留在一镜，对面那个人身上发生的事切反打，几个独立动作拆成几镜。观众要注意到的原因后面接它落在谁脸上；一个角色的动作作用到另一个角色身上，至少有接触、受动作的人、发出动作的人三镜。镜头一看清变化就切，停顿留在整串的最后。
4. 同一场景里只要不止一个镜头，一律做 Blender 分镜，所有镜头一次渲完。
5. 产品界面插进剧情时前后算同一场戏，写进同一次生成；玩家写的话由角色在剧情里演出来；界面背景取同一段视频里的一帧。
6. 审稿加复述测试。只把镜头表交给一个不知道主旨的新 agent 复述，复述不出主旨就算没过。多镜头场景的关键帧要按顺序连起来看。
7. 片单改成创意账本，见「创意账本」一节。

# 创意账本

飞书多维表格「Lunaverse 投放素材库」https://xcn662409uz0.feishu.cn/base/PFhVbuQfPaq0gGs2U19c6LWQnBd 。以创意为主维度，一条写好脚本的创意一行，草稿也留着，用状态看哪些做成了素材；原型在上一层，一个原型可以对应多条创意。

- 创意表：创意名、作品、KM、感情类型、原型、主旨、一件事、状态、返工次数、返工记录、王博反馈、脚本路径、成片链接、成片路径、制作人、交付日期；花费、安装、CPI、广告组从投放数据自动汇总，只算最新一次快照。
- 素材表、投放数据表各加了「所属创意」关联，投放数据表加了广告系列和广告组。
- 返工次数是交付后被打回重做的次数，不分环节；返工记录按原样写环节、问题和王博原话，不做分析，用来改 skill。
- 不喜欢某个创意的原因、聊天里说过的这段时间想调整的方向，写进项目 brand/audience-taste.md 的「被否掉过的写法」，不进表。写创意前两边都读。
- 通过或投放跑得好的创意可以换一部作品复用；被否的避开；同一部作品不重复同一个创意。
- 本机 agent 用王博的飞书账号读写；云端 runner 用 kaito 应用（Kaito的飞书 CLI）的机器人身份，只开了读和新增、更新记录，只加进这一个 Base，11-07 Rydia 配好并验证通过。

# 两个仓库和 0.0.1

- MobAI-Inc/MixReel-team：团队私有版，Buzz 和内部同事用，含 mixreel-lunaverse 技能、内部报告、内部安装脚本。
- MobAI-Inc/MixReel：公开版，只做产品广告，不加剧情模式。两边没有共同 git 历史。
- LinghuC2333/MixReel：个人仓库，10-30 后不再用。

钟文鼎 11-07 定的同步规矩，已写进团队版 AGENTS.md（MixReel-team#18）。
- 不许用脚本导出。团队版 skills/ 下除 mixreel-lunaverse 外的改动合并后，由一个 agent 读改动和公开版对应文件，按公开版自己的写法手工改，逐行查内部信息，跑测试后提一个 PR；另开一个不带上下文的 agent 审代码质量和泄露，没问题才合。
- 两边版本号一致，从 0.0.1 起依次递加。团队版记在 versions.json，公开版记在 CHANGELOG.md，两边打同名标签。
- 公开版 main 只走 PR，CI 的 test 必过，至少一人批准，禁强推禁删；外部贡献者的 CI 要先批准才跑。
